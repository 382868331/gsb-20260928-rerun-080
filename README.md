# 链上数据研究网站（人工区块索引版）

本版本只处理**人工导入**的区块数据，不连接任何公网节点。重点解决：

- 主链分叉后，新分支成为主链时，旧分支区块与其交易结果被撤回但仍可追溯；
- 交易位置、确认状态随主链切换整体变化，重复交易（同一笔交易出现在不同分叉）保留多个位置；
- 导入中断后重新提交同一批数据不会重复索引（按区块 Hash 幂等）；
- 页面看到的区块、交易、确认数与引用关系来自后端**同一索引版本**的快照。
- 页面各区域（拓扑、区块详情、交易索引、引用差异）与顶部版本选择器始终对应
  同一明确版本：导入/确认/裁决的响应直接携带最新快照并同步选择器；
  切换或载入失败时保留原视角，并显示“未完成”状态提示。
- 研究者可明确确认**链检查点**：检查点及之前为确认范围，之后为暂定范围；
  越过检查点的替代链只记为冲突（含引用差异），不自动撤销原确认，
  由研究者决定是否建立独立研究。
- **研究线**：两位研究者可以从相同资料出发，各自确认不同的检查点、
  各自导入新的区块与交易引用；两条研究线可以放在一起比较，并选择
  只接纳其中未确认的一段资料合并成新的研究线——某条线更长不会把
  另一条线的确认决定自动撤销。

统计分析在后续版本增加，本版本不实现。

## 架构

- `backend/`：Go 标准库实现（无第三方依赖，离线可用）
  - `internal/model`：区块、交易、版本快照等数据结构
  - `internal/store`：区块去重存储、历史版本快照、原子落盘（`data/store.json`）
- `internal/chain`：链重建引擎——高度计算、主链选择、分叉编号、确认数、交易位置与引用
  （含研究线比较/合并/线快照）
- `internal/api`：HTTP 接口
- `internal/sample`：内置的含分叉/重复交易/互引数据
- `frontend/`：React + Vite + TypeScript，`@xyflow/react` 画链拓扑

## 主链与撤回语义

- 高度不接受人工填写，由 `prev_hash` 链接关系计算，防止伪造高度。
- 主链选择：从每个链端点回溯累计 `work`，累计工作量最大者为主链；
  工作量相同以端点 Hash 字典序较小者为准（结果确定）。
- 每次导入使区块集合发生变化时，生成一个**不可变版本快照**：
  - 主链块 `canonical=true`，确认数 = `tip_height - height + 1`；
  - 被撤回的旧分叉块 `canonical=false`、确认数 0，保留块与交易并归入同一 `branch_id`；
  - 交易索引按交易分组，同一交易跨分叉的多次出现各有独立位置和确认状态（不是去重成一行）；
  - 交易引用来自 input 对前序交易的 `txid` 指向；同一交易在每个分叉位置各产生一条引用，
    每条引用同时标注**所在区块、链视角（分支）与当前有效性**：
    仅当引用方位置与引用目标都在当前主链上时 `active=true`，
    引用尚未到达（未解析）或只位于被撤回分叉时不提前认作当前有效。
- 历史快照全部保留，可通过版本切换查看旧结果，证明“旧分支仍可追溯”。
  切换历史版本后，引用解释（所在区块、链视角、有效性）也随该版本恢复。

## 检查点与冲突

- `POST /api/checkpoint`：研究者确认某区块为检查点（该区块必须已索引），
  确认后重建索引版本，快照携带 `checkpoint` 视图。
- 范围标记（`scope`）：区块、交易位置与交易引用分别标注
  `confirmed`（确认范围）/ `tentative`（检查点后的暂定范围）/
  `conflict`（越过检查点的冲突范围）/ `pending`（缺少父块或引用的待补充资料）/
  `reverted`（普通被撤回分叉）。
- 有检查点时，主链必须是经过检查点的链：迟到长分叉即使累计工作量更高，
  也只记入快照的 `conflicts`（端点、高度、累计工作量、状态），原确认不被撤销；
  检查点之后的分叉变化继续按工作量正常更新主链。
- `POST /api/conflicts/resolve`（`action=independent`）：研究者为冲突链
  建立独立研究，冲突保留但标记为已裁决；裁决同样生成新版本，
  旧版本的确认依据在重启后仍可追踪。

## 研究线：比较、合并与撤回

- 研究线只记录“属于该线的区块身份（按实际区块 Hash，不用高度或交易名
  代替）”与该线自己的确认/采用/撤回决定；区块内容仍全局按 Hash 去重。
- `POST /api/lines` 创建研究线；`POST /api/import` 带 `line_id` 时，
  本批区块同时计入该研究线并生成线版本（研究线有独立的版本序列，
  页面的链、检查点、交易详情与版本选择器共同指向当前研究线）。
- `POST /api/lines/checkpoint` 在研究线上确认检查点，只影响该线。
- `POST /api/lines/compare`（`{"a","b"}`）比较两条研究线并持久化结果：
  - `shared`：两线共有的事实（按区块 Hash 身份）；
  - `compatible_a/b`：各自独有且未跨越对方确认边界的后续资料；
  - `conflicts`：跨越确认边界的冲突（一方独有区块与另一方已确认
    检查点矛盾），只保留不自动撤销；父块缺失、祖先链尚不完整的
    资料无法证明矛盾，不算冲突，而是作为可接纳的待补充项保留；
  - `tx_notes`：同一交易在两条线不同分叉里的出现位置分别说明。
- `POST /api/lines/merge`（`{"comparison_id","name","keep","accept"}`）
  依据一次已持久化的比较合并为新研究线：
  - 共有事实与勾选的兼容资料进入新线，每个区块记录采用决定
    （来自哪次比较、哪条来源线），保存重开后可复核；
  - `keep=a|b` 选择保留哪一条线的确认（另一方的确认留在原线可回看）；
  - 相互冲突的部分记入 `deferred`（暂不采用），不拼接进新链，
    也不标记为无效；重复合并生成新的研究线，互不影响；
  - 只接纳部分后续资料时核对父区块与引用所需依据：缺少中间资料
    在快照中保留 `pending_gaps` 待补充范围，不拼接出从未存在的链；
    缺失父块的 gap-tip 同样作为有出处的待补充项被接纳保留，而不是
    直接拒绝；迟到的父块到达后重新判断是否属于已选确认的后续
    （缺口自动消失），只有已有证据证明冲突时才拒绝接纳。
- `POST /api/lines/withdraw`（`{"line","hash"}`）撤回该线中一份未确认
  资料（已确认范围不允许撤回）；撤回后快照中每条引用的
  `independent_sources` 标明哪些引用仍有独立来源。
- `GET /api/lines`、`/api/lines/state?line=&v=`、`/api/lines/versions?line=`、
  `/api/lines/comparisons` 查询研究线、线快照、线版本与比较历史。

## 分叉切换前后的引用差异

`GET /api/refdiff?from=<版本>&to=<版本>` 对比两个版本的引用关系，把变化分类为：

- `position_migrated`：同一引用的主链（当前有效）位置在区块间迁移；
- `target_changed`：引用目标交易变化，或目标解析到的位置/链视角变化；
- `confirmations_only`：位置与目标都不变，仅确认数变化；
- `added` / `removed`：仅出现在其中一个版本的引用。

前端“分叉切换前后引用差异”面板任选两个版本查看上述分类结果。

## 导入幂等与断点续传

- 区块按 `hash` 去重；内容一致的重复提交全部跳过，没有新区块时不产生新版本。
- 同 Hash 但内容不同视为数据冲突，整批拒绝（事务语义，不产生部分写入）。
- 存储采用临时文件 + 原子 rename，进程中断/重启后重放导入即可继续，不重复索引。

## HTTP 接口

- `GET /api/state?v=<版本>`：返回该版本完整快照（区块、交易位置、引用）；缺省返回最新版本。不存在的版本返回 404。
- `GET /api/versions`：历史版本元数据。
- `GET /api/refdiff?from=<版本>&to=<版本>`：两版本引用差异（位置迁移/目标变化/仅确认数变化）。
- `POST /api/import`：`{"label":"...","blocks":[...]}`，幂等导入并在有新增时生成新版本。
- `GET /api/sample`：内置分叉样例数据。
- `GET/POST /api/checkpoint`：查询 / 确认链检查点。
- `POST /api/conflicts/resolve`：裁决越过检查点的冲突（建立独立研究）。

前端所有渲染只使用一次 `/api/state` 返回的同一快照，不自行拼接不同请求结果。

## 运行

```bash
# 后端（默认 :8080，数据目录 ./data）
cd backend && go run ./cmd/server -addr :8080 -data ./data

# 前端（开发服务器 :5173，已配置 /api 代理到 8080）
cd frontend && npm install && npm run dev

# 生产构建
cd frontend && npm run build
```

打开页面后：展开“导入人工区块” → “载入内置分叉样例” → “导入并重建索引”，
可看到 B 链凭更高累计工作量取代 A 链；A 链区块变黄并标记“已撤回旧分叉”，
交易 `txA` 显示在 A2（撤回，0 确认）与 B2（主链，3 确认）两个位置。
