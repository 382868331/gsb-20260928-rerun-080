# 链上数据研究网站（人工区块索引版）

本版本只处理**人工导入**的区块数据，不连接任何公网节点。重点解决：

- 主链分叉后，新分支成为主链时，旧分支区块与其交易结果被撤回但仍可追溯；
- 交易位置、确认状态随主链切换整体变化，重复交易（同一笔交易出现在不同分叉）保留多个位置；
- 导入中断后重新提交同一批数据不会重复索引（按区块 Hash 幂等）；
- 页面看到的区块、交易、确认数与引用关系来自后端**同一索引版本**的快照。

统计分析在后续版本增加，本版本不实现。

## 版本一致性（前端）

- 导入完成后直接使用导入响应携带的新快照更新页面，顶部版本选择器与
  链拓扑、区块详情、交易索引、引用差异等所有区域始终对应同一版本。
- 切换或载入版本失败时，保留原视角不变，并显示“版本切换未完成”的
  未完成状态提示，可重试。

## 链检查点（研究者确认）

- 研究者可在主链区块上**显式确认检查点**：该区块及以前的历史成为
  **确认范围**，之后的主链与常规分叉为**暂定范围**；确认依据
  （当时版本、端点、链根到检查点的完整链段）持久化，重开后仍可追踪。
- 新资料提出**越过检查点的更重竞争链**（迟到长分叉）时，系统**不会
  自动撤销确认**：主链钉在包含检查点的链上，竞争链被标记为
  **冲突范围**，并把钉住视角与竞争链视角下的引用差异一并保留在快照中。
- 冲突由研究者裁决：
  - **采纳竞争链**：显式撤销原确认，主链按工作量重选；
  - **建立独立研究线**：保留原确认，竞争链登记为独立研究线，
    之后不再作为待决冲突，但区块仍标注冲突范围供核对。
- 检查点之后的分叉变化继续正常更新（不影响确认范围）。
- 每条交易引用标注所属范围：确认范围 / 暂定范围 / 冲突范围
  （引用目标落在冲突范围时整条引用按冲突范围对待）。

## 架构

- `backend/`：Go 标准库实现（无第三方依赖，离线可用）
  - `internal/model`：区块、交易、版本快照等数据结构
  - `internal/store`：区块去重存储、历史版本快照、原子落盘（`data/store.json`）
  - `internal/chain`：链重建引擎——高度计算、主链选择、分叉编号、确认数、交易位置与引用
  - `internal/api`：HTTP 接口
  - `internal/sample`：内置的含分叉/重复交易/互引数据
- `frontend/`：React + Vite + TypeScript，`@xyflow/react` 画链拓扑

## 主链与撤回语义

- 高度不接受人工填写，由 `prev_hash` 链接关系计算，防止伪造高度。
- 主链选择：从每个链端点回溯累计 `work`，累计工作量最大者为主链；
  工作量相同以端点 Hash 字典序较小者为准（结果确定）。
- 每次导入使区块集合发生变化时，生成一个**不可变版本快照**：
  - 主链块 `canonical=true`，确认数 = `tip_height - height + 1`；
  - 被撤回的旧分叉块 `canonical=false`、确认数 0，保留块与交易并归入同一 `branch_id`；
  - 交易索引按交易分组，同一交易跨分叉的多次出现各有独立位置和确认状态（不是去重成一行）；
  - 交易引用来自 input 对前序交易的 `txid` 指向；同一交易在每个分叉位置各产生一条引用，
    每条引用同时标注**所在区块、链视角（分支）与当前有效性**：
    仅当引用方位置与引用目标都在当前主链上时 `active=true`，
    引用尚未到达（未解析）或只位于被撤回分叉时不提前认作当前有效。
- 历史快照全部保留，可通过版本切换查看旧结果，证明“旧分支仍可追溯”。
  切换历史版本后，引用解释（所在区块、链视角、有效性）也随该版本恢复。

## 分叉切换前后的引用差异

`GET /api/refdiff?from=<版本>&to=<版本>` 对比两个版本的引用关系，把变化分类为：

- `position_migrated`：同一引用的主链（当前有效）位置在区块间迁移；
- `target_changed`：引用目标交易变化，或目标解析到的位置/链视角变化；
- `confirmations_only`：位置与目标都不变，仅确认数变化；
- `added` / `removed`：仅出现在其中一个版本的引用。

前端“分叉切换前后引用差异”面板任选两个版本查看上述分类结果。

## 导入幂等与断点续传

- 区块按 `hash` 去重；内容一致的重复提交全部跳过，没有新区块时不产生新版本。
- 同 Hash 但内容不同视为数据冲突，整批拒绝（事务语义，不产生部分写入）。
- 存储采用临时文件 + 原子 rename，进程中断/重启后重放导入即可继续，不重复索引。

## HTTP 接口

- `GET /api/state?v=<版本>`：返回该版本完整快照（区块、交易位置、引用）；缺省返回最新版本。不存在的版本返回 404。
- `GET /api/versions`：历史版本元数据。
- `GET /api/refdiff?from=<版本>&to=<版本>`：两版本引用差异（位置迁移/目标变化/仅确认数变化）。
- `POST /api/import`：`{"label":"...","blocks":[...]}`，幂等导入并在有新增时生成新版本。
- `GET /api/sample`：内置分叉样例数据。
- `GET /api/checkpoint`：当前检查点视图（含确认依据与冲突）与独立研究线。
- `POST /api/checkpoint`：`{"hash":"...","note":"..."}`，确认主链区块为检查点（生成新版本）。
- `DELETE /api/checkpoint`：显式撤销检查点确认。
- `POST /api/checkpoint/resolve`：`{"action":"adopt"|"branch","label":"..."}`，
  裁决越过检查点的冲突——采纳竞争链（显式撤销原确认）或建立独立研究线（保留确认）。

前端所有渲染只使用一次 `/api/state` 返回的同一快照，不自行拼接不同请求结果。

## 运行

```bash
# 后端（默认 :8080，数据目录 ./data）
cd backend && go run ./cmd/server -addr :8080 -data ./data

# 前端（开发服务器 :5173，已配置 /api 代理到 8080）
cd frontend && npm install && npm run dev

# 生产构建
cd frontend && npm run build
```

打开页面后：展开“导入人工区块” → “载入内置分叉样例” → “导入并重建索引”，
可看到 B 链凭更高累计工作量取代 A 链；A 链区块变黄并标记“已撤回旧分叉”，
交易 `txA` 显示在 A2（撤回，0 确认）与 B2（主链，3 确认）两个位置。
